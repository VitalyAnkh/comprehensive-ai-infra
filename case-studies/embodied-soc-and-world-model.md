## 为什么模型前向只需 8.5 ms，端到端控制环却超过 40 ms

在人形机器人与端到端自动驾驶真机联调中，工程团队经常遇到一个反直觉现象：将视觉—语言—动作模型（如基于 [Qwen3-8B 配置](../configs/models/qwen3-8b/config.json) 裁剪的机载视觉主干与 `150M` 流匹配动作头）通过 TensorRT 静态图部署到 `NVIDIA Jetson Thor` 后，单独测量模型内核前向耗时仅约 `8.5 ms`，但从相机曝光结束到关节力矩下发的端到端闭环延迟却高达 `35–45 ms`，且 `P99.9` 尾部抖动接近 `10 ms`。

拆解主机与加速器之间的数据通路即可定位根因。以人形机器人常见的 **6 路 `1920×1200@60fps` GMSL2 全局快门相机**为例，ISP 输出标准 `NV12`（`YUV 4:2:0`，平均每像素 `1.5 B`）格式时，单帧字节数为：

$$B_{\mathrm{frame}} = 1{,}920 \times 1{,}200 \times 1.5 = 3{,}456{,}000\ \mathrm{B}\ (\approx 3.296\ \mathrm{MiB})$$

6 路相机在 `60 FPS` 下的原始传感器流入速率为 $6 \times 60 \times 3{,}456{,}000 = 1{,}244{,}160{,}000\ \mathrm{B/s} \approx \mathbf{1.244\ \mathrm{GB/s}}$。若沿用实验室原型阶段的默认 `V4L2 + ROS 2 DDS + OpenCV + CUDA` 软件栈，每一帧图像在进入 ViT Patchify 算子前会经历以下物理内存遍历：

1. **ISP DMA 写出**（`1` 次写）：相机 CSI-2 解串后由硬件 ISP 将 `NV12` 帧写入内核 `V4L2` 缓冲区；
2. **用户态采集拷贝**（`1` 读 + `1` 写）：采集节点从 `V4L2` 映射区拷入用户态消息对象；
3. **`ROS 2` DDS 序列化与环回套接字传输**（`1` 读 + `1` 写）：中间件将图像序列化进发送缓冲，经内核环回协议栈拷入订阅进程接收缓冲；
4. **CPU 色彩空间转换**（`1` 读 + `1` 写）：CPU 调用 `cvtColor` 将 `NV12` 展开为 `RGB888` 或 `FP16` 平面张量；
5. **主机到设备拷贝**（`1` 读 + `1` 写）：调用 `cudaMemcpyHtoD`（若源缓冲未页锁定，驱动内部还会追加一次临时锁页缓冲中转）送入 GPU 可见内存。

即便不计非锁页二次中转，`1` 次 ISP 写出加上 `4` 次全帧读写拷贝也意味着每帧数据在统一 LPDDR5X 上往返 **9 次 DRAM 遍历**，等效消耗 $9 \times 1.24416 \approx \mathbf{11.20\ \mathrm{GB/s}}$ 内存带宽；叠加 Linux 普通进程调度、序列化内存分配与页表缺页中断，传感到 ViT 输入的 `P99` 传输耗时达 **`18.60 ms`**，`P99.9` 抖动达 **`9.40 ms`**。

## 硬件信号量同步的零拷贝管线与 Iceoryx 槽位守恒

消除这一延迟黑洞的核心原则是**让像素自离开 ISP 起永不经过 CPU 拷贝与内核协议栈**，利用机载异构 SoC 的统一物理内存架构建立 `CSI/GMSL -> ISP -> Linux DMA-BUF / NvSciBuf -> GPU ViT` 硬件直通管线：

- **统一物理页分配与 IOMMU 预映射**：启动阶段由 `NvSciBuf`（或通用 Linux `DMA-BUF` 堆）预分配对齐物理页池，同时完成 ISP 写引擎与 GPU SMMU 页表固定映射；
- **硬件同步原语（`NvSciSync` / Sync File Fence）**：ISP 开始写第 $k$ 帧时预先签发硬件围栏（Fence），GPU 侧采集流直接挂载 `cudaWaitExternalSemaphoresAsync`，当 ISP 写完最后一行像素时通过片上硬件信号量在微秒内唤醒 GPU，无需 CPU 线程介入唤醒；
- **`ROS 2 Iceoryx` 无锁共享内存指针发布**：进程间仅通过 `Iceoryx` 环形队列交换 **64 字节固定描述符**（含槽位句柄、PTP 曝光中心时间戳与围栏 ID），彻底消除百万字节级 DDS 序列化；
- **ViT 首层融合采样核**：GPU 直接在 Patchify 卷积首层算子内原位读取 `NV12` 亮度与色度平面并完成归一化，省去独立色彩转换写回。

在该零拷贝路径下，每帧仅发生 **2 次 DRAM 遍历**（`1` 次 ISP 写出 + `1` 次 GPU 融合算子直读），内存流量降至 **`2.49 GB/s`**（压缩 **`4.50 倍`**），传感传输 `P99` 耗时收敛至 **`0.85 ms`**（提速 **`21.88 倍`**），`P99.9` 抖动降至 **`0.14 ms < 0.15 ms`**。同时，为防止慢速 `System 2 VLM` 借用（Borrow）历史帧期间阻塞 `60 Hz` ISP 写入，共享内存池单路最小槽位数必须满足无饥饿守恒式 $S_{\min} = 1_{\mathrm{write}} + 1_{\mathrm{queue}} + \sum_j H_j$：当 `System 2`、`System 1` 与黑匣子编码器并发借用配额分别为 `1, 1, 2` 时，单路需配置 **`6` 个槽位**（6 路共 `36` 个槽位，常驻池体积 **`118.65 MiB`**）。

## 异构引擎共享 SLC 干扰与内存控制器 QoS 隔离

统一物理内存消除了显式拷贝，却带来了第二个硬件隐患：**多异构引擎争抢片上系统级缓存（SLC）与内存控制器队列**。当单颗边缘 SoC（`64 MiB`、`16-way` SLC，`273 GB/s` LPDDR5X）同时运行双目立体匹配（`PVA`）、`Qwen3-VL` 慢系统（`GPU`）以及实时锁步核上的 `1 kHz` 全身力控模型预测控制（`R52/CPU` MPC，硬截止期 `1.00 ms`，热工作集 `3.2 MiB`）时，GPU 流式扫描数十 GB 权重会在亚毫秒内冲刷整片共享 SLC，使实时核缓存命中率从 `98.5%` 跌至 `12.0%`，叠加 DRAM 突发队列阻塞后，`1 kHz` 力控环的最坏执行时间（WCET）恶化至 **`1.82 ms > 1.00 ms`**，引发力矩周期违约。

工程根治方案必须同时在缓存层与内存控制器层施加硬件隔离：
1. **SLC 路分区（Way-Partitioning）与流式旁路提示**：将 `16-way` SLC 中的 `2 ways`（`8 MiB`）专有锁定给实时核（容纳 `3.2 MiB` 热工作集并留出双缓冲裕量），`4 ways`（`16 MiB`）划归 `PVA` 与 `System 1` 快环，其余 `10 ways`（`40 MiB`）供 `GPU System 2` 激活使用，同时对大模型只读权重页标记 `Bypass-SLC` 防止无效冲刷；
2. **内存控制器紧急虚通道与带宽令牌桶**：为实时核访存事务配置最高优先级抢占虚通道（`Urgent VC`），并将非实时 `GPU + PVA` 聚合带宽上限整形在 `205.0 GB/s`（占峰值 `273 GB/s` 的 `75.1%`），避开 DRAM 控制器在 `> 80%` 利用率后的排队延迟陡增区。隔离后 `1 kHz` 力控环 WCET 稳定回落至 **`0.41 ms <= 1.00 ms`**（加速 **`4.44 倍`**）。

## 闭环神经世界模型回归评测与 145 倍成本压缩

在策略发版上线前，离线验证集上的开环动作均方误差（Open-Loop Action MSE）极易产生误导：某个在专家轨迹上过拟合出更低开环 MSE（`0.0041` vs. `0.0048`）的候选策略，一旦部署到闭环环境中，微小的早期接触偏差就会改变下一帧相机视角并诱发协变量偏移（Covariate Shift），导致碰撞包络越界率飙升至 **`14.2%`**（任务成功率跌至 `54.0%`）。

若完全依赖真机工位做大规模长尾回归，测试 `1,000` 个长程操作场景 × 每场景 `100` 次位姿/光照微扰（共 **`100,000` 条闭环轨迹**，单次含复位平均耗时 `120 s`）需要 `3,333.33` 台时；即便投入 10 个真机工位并行运转也需耗费 `333.33 h`（约两周），综合工位折旧与安全员值守成本高达 **`111,360` 美元**。通过构建 **64 卡动作条件闭环神经世界模型评测集群（`3DGS` 静态几何脚手架 + 4 步蒸馏动作条件视频 `DiT` + 实时碰撞安全包络检测器）**，集群聚合吞吐可达 `250,000 rollouts/h`，仅需 **`0.40 h`（`24 分钟`，`25.6 GPU-h`）** 与 **`768` 美元** 机时成本即可完成全量 10 万条闭环回归，实现 **`145.0 倍`** 评测成本压缩与超过 **`800 倍`** 的发版反馈提速，将高风险策略拦截在接触真实物理世界之前。
